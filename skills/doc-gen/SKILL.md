# 项目文档生成

深入扫描项目代码，生成一套**完整且相互独立**的开发文档集：每个开发流程、每个功能流程单独成篇，文档内图表尽可能完整。

## 流程

### 第一步：项目分析

全面扫描项目，理解其全貌并**枚举所有流程**：

- `package.json` — 依赖、项目元信息 → 推断项目类型（CLI/库/Web 应用/工具集）
- `npm scripts` / Makefile / CI 配置 — 推导完整开发生命周期：环境搭建 → 开发 → 构建 → 测试 → 发布 → 部署
- 目录树 — 各目录职责，识别模块边界（画架构图的依据）
- 入口文件 — 主流程
- 源码 — 核心模块、导出 API、关键函数、状态流转
- 配置文件 — 构建、测试、发布、部署相关
- CLAUDE.md / README.md — 已有项目说明
- `git log` — 近期改动趋势、核心功能流程线索

分析完成后输出三份清单：

1. **开发流程清单** — 项目生命周期中的每个流程（如：初始化、开发、构建、测试、发布、部署）
2. **功能/业务流程清单** — 用户可感知的每个功能流程（如：安装技能、生成文档、升级）
3. **模块清单** — 架构图所需的模块及其关系

### 第二步：确定文档清单

**核心原则：一个流程一份文档，禁止把多个流程堆进同一份文档。**

基于第一步的三份清单，按以下分类生成文档清单（每个流程至少一份独立文档），让用户确认增删：

**总览类（必有）：**
- 项目概述 — 定位、能力、快速上手
- 架构总览 — 模块关系架构图、数据流向
- 目录结构 — 每个目录/文件的职责

**开发流程类（每个流程独立一份）：**
- 环境搭建与初始化 — 从零到可运行的完整流程
- 日常开发工作流 — 修改代码 → 验证 → 提交的循环
- 构建流程 — 构建步骤、产物、常见问题
- 测试流程 — 测试组织、运行、编写规范
- 发布流程 — 版本管理、发布步骤
- 部署流程 — 部署方式、环境、回滚

（按项目实际有的流程裁剪，项目没有的流程不生成）

**功能流程类（每个核心功能独立一份）：**
- 每个核心功能/业务流程一份文档 — 触发方式、执行步骤、涉及模块、产出

**参考类（按需）：**
- API/命令参考 — 逐个函数/命令的说明
- 配置说明 — 每个配置项的含义与默认值
- FAQ / 常见问题

### 第三步：逐份生成

按总览 → 开发流程 → 功能流程 → 参考的顺序逐份撰写。

**每份文档的硬性要求：**

1. **独立成篇** — 一份文档只讲一个流程/主题，相关但不相同的内容拆分到独立文档并互相链接，不允许合并
2. **图表完整** — 每份文档至少一张 Mermaid 图，按内容选型，复杂主题多图并用：
   - 开发流程/功能流程 → `flowchart` 流程图（主流程 + 分支判断 + 异常/失败路径，**不能只画 happy path**）
   - 架构/模块关系 → 架构图（模块 + 数据流向）
   - 多方调用/通信 → `sequenceDiagram` 时序图
   - 状态变化 → `stateDiagram-v2` 状态图
   - 数据模型 → `erDiagram` 实体关系图
   - 用户操作交互 → 交互流程图（用户视角的操作步骤与系统反馈）
3. **代码引用** — 关键描述带 `文件路径:行号`
4. **可运行示例** — 命令、代码示例可直接复制执行
5. **异常与边界** — 每个流程文档覆盖失败场景与排查方法

每份生成后向用户确认，再继续下一份。文档数量多时可以分批确认。

**并行分派（多 Agent）约束：**

- 分派前先确定**全部文档的文件名清单**，将确切文件路径原样写进各 Agent 任务书，禁止 Agent 自行命名/改名——文件名不一致是并行生成后死链的头号来源
- 任务书中的互链规范必须给出相对路径约定（同目录 `./xxx.md`、跨目录 `../dir/xxx.md`）并明确各目录实际文件名
- 全部完成后必须做死链扫描（方法见第五步），输出为空才算完成

### 第四步：完整性自检

全部生成后自检：

- 对照第一步的流程清单，**每个流程是否都有独立文档**？
- 每份文档的图表是否覆盖了分支与异常路径（不是只有 happy path）？
- 文档间是否互相链接（而非重复内容）？
- **死链扫描**（docs 站存在时必须执行，输出为空才算通过）：

```bash
cd docs && find . -name '*.md' -not -path './node_modules/*' -print0 | while IFS= read -r -d '' f; do
  dir=$(dirname "$f")
  grep -oE '\]\([^)#]+\.md' "$f" 2>/dev/null | sed -E 's/\]\(//' | while read link; do
    if [ ! -f "$dir/$link" ]; then echo "DEAD: $f -> $link"; fi
  done
done | sort -u
```

发现缺口时补齐后再进入下一步。

### 第五步：注册到文档站

更新 `docs/.vitepress/config.mts` 侧边栏，按分类分组注册所有文档（总览 / 开发流程 / 功能流程 / 参考）。

## 原则

- **独立成篇** — 一个流程一份文档，宁可文档多而细，不要少而堆砌
- **图表优先** — 能用图说清楚的先画图，图覆盖主流程、分支与异常路径
- **以代码为准** — 文档内容基于实际代码，不凭空编造
- **优先检测已有文档** — 如果文件已存在，询问是覆盖还是补充
- **引用代码** — 关键描述带文件路径和行号
- **文件名先行** — 并行生成前锁定文件名清单，死链扫描通过才算完成
