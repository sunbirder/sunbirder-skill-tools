# VitePress 侧边栏同步

文档文件生成了，但 `docs/.vitepress/config` 的侧边栏没有登记 → 页面在站点菜单里看不到、无法到达。本技能扫描全部文档文件与配置的差异，补齐菜单入口。

## 流程

### 第一步：扫描文档文件清单

```bash
cd docs && find . -name '*.md' \
  -not -path './node_modules/*' \
  -not -path './.vitepress/dist/*' \
  -not -path './.vitepress/cache/*' \
  | sed 's|^\./||;s|\.md$||' | sort
```

`index.md` 特殊处理：`guide/index.md` 对应链接 `/guide/`（目录入口）。

同时提取每个文件的人类可读标题（优先级）：frontmatter `title:` > 正文第一个 `# 标题` > 文件名。

### 第二步：解析已注册条目

找到配置文件 `docs/.vitepress/config.{mts,ts,js}`，提取 nav 与 sidebar 中全部 link：

```bash
grep -oE "link: '[^']+'" docs/.vitepress/config.mts | sed "s/link: '//;s/'//"
```

外链（`http(s)://` 开头）跳过，不参与对比。

### 第三步：对比输出差异表

| 文件 | 状态 | 建议操作 |
|------|------|----------|
| `docs/dev/build.md` | 未注册 | 加入侧边栏 |
| sidebar 中 `/guide/old-page` | 死链 | 文件已删 → 移除条目；已改名 → 修正路径 |
| `docs/dev/test.md` | 已注册 | 无需处理 |

三类问题：

- **未注册** — 文件存在、菜单里没有（最常见）
- **死链** — 菜单里有、文件不存在（改名/删除后遗留）
- **错组** — 已注册但分组或顺序不合理（可选修正）

### 第四步：确认修正策略

把计划展示给用户确认：

- **分组规则** — 按目录映射现有分组（如 `guide/dev/` → "开发流程" 组）；无匹配分组时新建
- **标题规则** — 用第一步提取的标题作为菜单 text
- **排序规则** — 总览类在前，其余按目录/字母序
- 死链条目：能对应到改名后的文件就修正路径，否则删除条目

### 第五步：修改配置并复验

- 编辑 config，只增删必要条目，不动其他配置（最小改动）
- 复扫：文件清单 vs 已注册清单，**diff 为空才算完成**
- 向用户报告：新增 N 条、修正 N 条、删除 N 条
- 如文档站在运行，提醒用户 VitePress 会热更新配置（config 改动需刷新页面）

## 原则

- **文件为准** — 所有公开文档页面都必须能从菜单到达
- **最小改动** — 只增删必要条目，不重构已有配置
- **先确认再改** — 差异表和修正策略先给用户看
- **复验收尾** — 改完必须复扫，diff 为空才算完成
