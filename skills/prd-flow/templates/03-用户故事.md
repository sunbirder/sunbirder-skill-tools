# 用户故事清单 · 〈产品/功能名〉

## US-F〈n〉-〈序号〉

> **作为** 〈具体 persona，禁"user"〉，
> **我想要** 〈可度量的用户动作〉，
> **以便** 〈业务价值，不许复述 I want to〉。

**AC（Given-When-Then；只能一个 When、一个 Then）：**

1. **Given** 〈前置状态〉 **When** 〈动作（对齐 I want to）〉 **Then** 〈可观察结果（对齐 so that，可证明）〉（happy path）
2. **Given** … **When** … **Then** …（edge case）
3. **Given** … **When** … **Then** …（negative path）
4. （可选）性能/无障碍：〈数字指标〉
5. （可选）集成点：〈与什么交互〉

**INVEST 自检**

| 项 | ✅/⚠️ | 不合格时的修法 |
| --- | --- | --- |
| Independent 独立 | | 有依赖 → 拆或合并 |
| Negotiable 可协商 | | 含技术细节 → 删掉（放开发设计） |
| Valuable 有价值 | | → 重写 So that |
| Estimable 可估算 | | 上下文不够 → 先建 Spike |
| Small 小（≤1 sprint） | | 太大 → 拆（标题含 AND/多角色/多 CRUD 都是信号） |
| Testable 可测 | | → 补具体 AC |

## Sanity Check（提交前 5 问）

- [ ] PO（非技术）看得懂吗？
- [ ] Junior dev 能估算吗？
- [ ] QA 能从 AC 写出 ≥5 条测试用例吗？
- [ ] 与 backlog 其他故事不重叠吗？
- [ ] "So that" 真有价值还是 "I want to" 的回声？
