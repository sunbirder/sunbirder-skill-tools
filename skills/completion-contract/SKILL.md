# 生成 Completion Contract(完成契约)

一句话:开工前把「什么叫做完」钉成五字段契约,验收**只认命令的真实输出,不认口头宣称**。语义源自 Hermes Agent v0.18(Judgment Release)的 Completion Contract;本技能将其落地为仓库工件。

## 何时使用 / 何时不用

- ✅ 多步实施开工前(模块落地、功能开发、迁移);需求对「做完怎么证明」有歧义;工作要交给 Agent 长循环执行、需要停止条件
- ❌ 一次性单步任务(杀鸡用牛刀);已完成工作的证据归档(那叫验收报告/验证记录,是另一种工件,别混用)

## 流程(四步)

1. **确认目标与 slug** — 一句话目标 + 契约落盘路径(默认 `.scratch/<slug>/completion-contract.md`)。范围过大无法独立验收 → 先拆分,一份契约只钉一项
2. **实地勘察** — 为 verification 寻找**真实可执行**的命令:构建/测试入口、启动方式、配置文件路径、现有检查脚本。**禁止编造命令**——核对不到的一律转 stop_when,不许硬写
3. **逐字段起草** — 按下方模板与质量红线
4. **用户确认后落盘** — 实施期间契约修订必须经用户裁定并记录

## 五字段质量红线

| 字段 | 红线 |
|------|------|
| `outcome` | 写**最终可观测状态**(「X 可运行且 Y 通过」),不写过程任务清单(「完成 A/B/C」是任务列表,不是结果) |
| `verification` | 每条 = 真实可执行命令 + 通过标准,能独立跑;整条契约的灵魂,宁缺勿假 |
| `constraints` | 引用**真实存在**的纪律/规范/文件(ADR、CLAUDE.md 约束、兼容性承诺),不虚构编号 |
| `boundaries` | 「允许写 / 不允许写」两栏,具体到目录路径;不留「其他按需」的口子 |
| `stop_when` | 具体触发条件(环境缺失、规范冲突、连续 N 轮失败、需要越界改动);至少 2 条;不写「遇到困难时」这种不可判定的表述 |

## 判定规则(契约必含此节)

> 全部 verification 真实输出达标 **且** outcome 逐项观测确认 → Done;任一不满足 → Not Done。禁止部分宣称完成,禁止以口头总结替代命令输出。

## 常见错误(含真实基线失败)

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 事后补写当契约 | 失去事前约束价值,Verification 沦为追认 | 开工前生成;已完成的工作写验收报告 |
| verification 编造不存在的命令 | 裁判一执行就失败,契约变废纸 | 实地勘察实物;核不出 → stop_when |
| outcome 写成任务清单 | 无法观测,验收各说各话 | 写最终状态,每条可用「看什么/跑什么」验证 |
| boundaries 不写具体路径 | 实施者越界改底座/上游 | 两栏清单,具体到目录 |
| 没有 stop_when | 死循环、自作主张扩大范围 | ≥2 条可判定的暂停条件 |

## 输出模板

```markdown
# Completion Contract — <目标工作>

- **语义**:Hermes Agent v0.18 五字段事前验收协议;验收只认命令真实输出
- **状态**:待实施(开工前钉死)

## outcome — 完成的可观测状态
| # | 状态 |  ← 每条可观测、可独立确认

## verification — 裁判执行的命令
| # | 命令/操作 | 通过标准 |  ← 全部真实可执行

## constraints — 不得破坏
| # | 约束 | 依据 |  ← 引用真实规范

## boundaries — 作用域
- 允许写:<具体路径>
- 不允许写:<具体路径>

## stop_when — 必须暂停问人
1. <可判定条件>(至少 2 条)

## 判定
<判定规则原文照抄>
```
