# prd-flow

PRD 八步需求文档工作流 — 把一个模糊想法变成八份可交接的需求工件：澄清拷打 → 问题定义 → 范围圈定 → 用户故事 → 场景与状态流转 → PRD 组装 → 评审预演 → 任务拆解。

方法论源自开源 prd-flow 工作流（上游为 Mike Cohn 用户故事、BDD GWT、INVEST、Pre-mortem 等行业共识的工程化集成），本仓库版本为 sunbirder 适配。

## 触发条件

- 输入 `/skill:prd-flow`
- 说「帮我做 X 的需求分析」「把想法变成 PRD」「只帮我写用户故事」「评审这份 PRD」「拆任务/排期」
- 即使没提「PRD」或「需求分析」，只要是在把产品/功能想法变成可开发、可验收的文档

## 八步与产出

| 步 | 产出 | 核心规范 |
| --- | --- | --- |
| 01 澄清拷打 | 00-澄清记录.md | 决策树提问；结论标证据三态；挂起项给 Owner |
| 02 问题定义 | 01-问题定义.md | 共情五段叙事 + 一句话收口 + 北极星/Guardrail |
| 03 范围圈定 | 02-范围说明书.md | P0 ≤ 5；明确不做每条附原因 |
| 04 用户故事 | 03-用户故事.md | 三段式 + GWT；每故事 ≥3 条 AC（happy+edge+negative） |
| 05 场景与状态 | 04-场景与状态/ + pages/ | 流程图三分支；页面五态；字段表 |
| 06 PRD 组装 | 05-PRD.md | 12 节模板；🔶/🔵 内联标记；跑 validate.py 校验 |
| 07 评审预演 | 06-预演评审记录.md | 三道闸：清单机审 → Tigers 思想实验 → 场景走查 |
| 08 任务拆解 | 07-任务拆解.md | ≤2 故事/≤24 人时；追溯矩阵 ≥95% |

## 五条全局纪律

1. **工件落盘**：产物统一写入 `docs/reqs/<产品名>/`，文件名固定，下游只读上游文件
2. **证据三态标注**：`[代码证据 路径]` / `[文档证据 路径]` / `[推断]`，确认后升级 `[用户确认 日期]`
3. **确认留痕**：三态（AI推断/用户确认/客户确认）写入 `_状态.md`；口头确认不算数，未确认不得进下一步
4. **提问协议**：每轮 ≤4 问、每问带选项与推荐答案；事实自己查，决策才问人
5. **禁止代用户拍板**：优先级、取舍、边界属于用户决策

## 核心特性

- **中断续跑**：读 `_状态.md` 从上次停下的地方继续，不重问已确认问题
- **版本 = 需求批次**：版本内迭代零记录，只有开版/定版产生痕迹；定版快照进 `versions/`
- **术语表机制**：多轮迭代项目维护 GLOSSARY.md（术语 + 定义 + Avoid 项），工件用词遵循之
- **技能衔接**：方案分歧分流 `discuss`；任务级验收协议衔接 `completion-contract`
- **确定性校验**：Step 06 强制跑 `scripts/validate.py`，FAIL 不得声称完成

## 支持的启动模式

| 你说 | 模式 |
| --- | --- |
| "帮我做 X 的需求分析" | 全流程 01→08 |
| "继续上次的 X" | 续跑 |
| "只帮我写用户故事" | 单步（缺上游时声明假设） |
| "评审这份 PRD" | 仅 Step 07 |
| "拆任务/排期" | 仅 Step 08 |

## 安装

```bash
node bin/cli.js add prd-flow          # 单装
node bin/cli.js install               # 全量安装（含本技能）
```

技能含 `references/question-playbook.md`（提问剧本）、`scripts/validate.py`（PRD 校验器）、`templates/`（7 份工件模板），CLI 会整目录递归复制。
